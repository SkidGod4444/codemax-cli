# codemax-cli

One terminal for every coding agent the user pays for. codemax drives Claude Code, Codex, OpenCode, Grok, Cursor and Antigravity CLI (Google's successor to Gemini CLI) from one chat UI, keeps one conversation and project history across them, and hands the task to the next agent when one runs out of quota.

## Commands

```sh
bun install
bun run dev            # run the CLI from source (same as `codemax` after `bun link`)
bun test               # all tests; no logins, no network, no quota
bun test test/x.test.ts
bun run typecheck
bun run build          # dist/codemax, re-signed on macOS
bun scripts/ui-preview.ts <dir>   # colour snapshots (dark + light HTML) of a scripted session
bun scripts/type-bench.ts [rows]  # typing latency in the test renderer: idle, streaming (CODE=1 LINES=1500 for a big code block), long prompt, @file over 20k files
ROWS=600 bun scripts/pty-bench.ts # end to end on the real terminal renderer in a PTY: key → screen, output KB/s, with mouse motion

cd web && bun run dev  # landing page on http://localhost:3000
cd web && bun run lint && bunx tsc --noEmit && bun run build
```

## Layout

- `src/cli.ts` entry and subcommands. `src/config.ts` reads `~/.codemax/config.json`.
- `src/engines/` one engine per agent protocol, all emitting one normalized event stream (`types.ts`). `acp.ts` is the generic ACP client (Claude via `@agentclientprotocol/claude-agent-acp` (formerly `@zed-industries/claude-code-acp`), OpenCode, Grok, Cursor, Antigravity). `codex.ts` speaks native `codex app-server` JSON-RPC. `env.ts` builds every agent's environment.
- `src/chat/` the OpenTUI chat UI: transcript, slash palette, permission dialog, markdown and diff styling, theme.
- `src/core/` ledger, handoff brief, usage and pricing, budgets, checkpoints, `@file`, doctor, quota.
- `src/tui/`, `src/adapters/`, `src/transcripts/` the embedded-terminal fallback (`codemax --tui`, `--raw`) and transcript tailing for agents without a protocol.
- `test/` runs the real `ChatApp` in OpenTUI's test renderer against scripted fake ACP agents. `test/setup.ts` (bunfig preload) gives each file its own `CODEMAX_HOME`.
- `install.sh` (macOS/Linux, adds Bun's bin to the shell profile) and `install.ps1` (Windows PowerShell, adds it to the user PATH) are the one-line installers. `install.sh`: clones the newest release tag into `~/.codemax/cli`, installs Bun if asked and updates a Bun older than 1.3 (`bun upgrade`, else Bun's own build into `~/.bun`; `install.ps1` the same), and writes `~/.bun/bin/codemax` as a script that runs `src/cli.ts` with that exact Bun (not whatever `bun` is first on PATH). The site's `/install` and `/install.ps1` redirect to them. On Windows, agents are launched through `src/core/spawn.ts` (`.cmd` shims via cmd.exe); `--tui`/`--raw` are Unix-only. Install on Windows is CI-tested (`.github/workflows/install.yml`), and the whole test suite runs on Windows, macOS and Linux (`.github/workflows/test.yml`; the `--tui` tests skip on Windows); sessions with real agents on Windows are not. Test it with a temp `HOME` and `CODEMAX_REPO=$PWD`.
- `bin/codemax.cjs` is the npm entry (`npm i -g codemax-cli`): a Node launcher that runs `src/cli.ts` with Bun from the matching `@oven/bun-<platform>` optional dependency (npm installs only the one for the machine, with no install script), first; only without it a `bun` npm package or a `bun` on PATH, and never a Bun older than 1.3 (a stale global `bun` npm package once ran codemax on 1.2.19, found through the debug log). With no Bun 1.3+ on PATH, the launcher also makes the bundled Bun the user's global `bun`, once (`linkGlobalBun`, the owner's choice): a link at `~/.bun/bin/bun` (a hard link or copy on Windows), that folder first in the shell profile (Windows: the user PATH), a one-line note, marker `~/.codemax/global-bun.json`; nothing is downloaded and an existing `~/.bun/bin/bun` is never replaced; `CODEMAX_NO_GLOBAL_BUN=1` (and CI) skip it. `src/cli.ts` warns when it runs on an older Bun anyway. `bin/codemax` (Bun shebang) is what the install scripts link. Published on npm as `codemax-cli` (the site's install box shows `npm install -g codemax-cli`). Publishing needs the owner's `npm publish` with browser 2FA approval; `.github/workflows/npm.yml` tests the package (or, via workflow_dispatch with source=registry, the published one) on macOS, Linux and Windows.
- `web/` the Next.js landing page. Read `web/AGENTS.md` first: this Next.js version differs from older ones, and its docs are in `web/node_modules/next/dist/docs/`.

## Rules that never bend

These come straight from the project owner. Do not offer options that weaken them.

- **No one-shot headless modes.** Never drive agents with `claude -p`, `codex exec`, `opencode run` and similar. They auto-approve and drop permission prompts. Agents run only over interactive protocols (ACP, Codex app-server) where permission requests reach the user.
- **Subscriptions only.** `src/engines/env.ts` always strips vendor API-key variables. There is no opt-out. `codemax doctor --fix` removes keys from `~/.claude/settings.json`.
- **No auto-approval.** Every new engine maps the agent's approval requests to `permission_request` events.
- **Never touch the user's git state.** Checkpoints use a private index and `refs/codemax/checkpoints`.
- Commit or push only when the user says "push".
- **Engines pass tool input, output, diffs and files uncut** (`tool_call` / `tool_update` fields); only the journal caps them. Do not truncate in an engine.
- **License is AGPL-3.0-only** plus a section 7 permission in `NOTICE` for the non-free agent SDKs and CLIs codemax drives (for example `@anthropic-ai/claude-agent-sdk`). The name and logo are governed by `TRADEMARKS.md`. Check a new dependency's license before adding it. Outside contributions need a signed `CLA.md` (checked by `.github/workflows/cla.yml`); never merge an outside pull request while that check is red.
- **Users install release tags, not `main`.** `install.sh` picks the newest `vX.Y.Z` tag (falls back to `main` only before the first release). Pushing to `main` ships nothing; releasing does. To release, when the user asks: bump `version` in `package.json`, write the version's entry in `src/core/whatsnew.ts` yourself, without being asked (at most 4 user-facing lines under 70 characters, what users get: shown for 5 s after /update; `test/update.test.ts` fails without it), commit, push, wait for the npm / Install / Keep awake workflows to pass, then `git tag vX.Y.Z && git push origin vX.Y.Z`, `gh release create`, and `npm publish` (the owner approves in the browser within a few minutes; run it under `script` so npm waits). A release is done only when `npm view codemax-cli version` shows it: npm installs are only offered updates that reached npm, installer installs are offered GitHub releases (`src/core/update.ts`).

## Design decisions

| Decision | Why |
|---|---|
| codemax owns the UI; agents are engines (since v0.3) | One consistent chat, native ledger of every turn, handoffs without terminal-state bugs. `PLAN.md`'s opening "wrap the real TUIs" section is history; that path survives only as `--tui` and `--raw`. |
| OpenTUI for the terminal UI | Bun-native, embedded terminal (Ghostty VT) for the fallback pane; Ink has none. |
| Codex via its own app-server, not the ACP adapter | The community adapter rejects ChatGPT-plan models. |
| Claude via the Zed ACP adapter with `CLAUDE_CODE_EXECUTABLE` | Runs the user's own installed `claude` and login. |
| OpenCode gets an inline "ask" permission config | Otherwise it acts without asking. |
| Cursor via `cursor-agent acp` (hidden command, Cursor Agent 2026.10+) | Verified: it asks before shell commands (allow once / always / reject) and honours a reject; file edits it writes straight to disk without asking (checked live: only a diff after the fact), so codemax says so when Cursor starts (`EDITS_WITHOUT_ASKING`). Models and modes (agent / plan / ask) come as config options. It reports no token usage. Changing its model persists in Cursor's own settings. |
| Model menus show only what the agent reports, never a list of ours | ACP agents report models in the session (or config options); Codex through `model/list` (hidden models skipped, 4 s timeout, falls back to the current model). Menus show display names, newest first by the version in the name, Default/Auto pinned (`src/chat/models.ts`), and scroll so every entry is reachable. Codex's `/effort` levels come from the current model's `supportedReasoningEfforts`. |
| Model switching prefers the ACP `model` config option; else raw `session/set_model` | SDK 1.9 dropped `unstable_setSessionModel`; the Claude adapter still answers `session/set_model`. Agents with one model (Grok on most plans) say so; `/effort` sets a `thought_level` option. |
| Antigravity via Google's own ACP server (`src/engines/antigravity.ts`) | `agy` (1.4) has no ACP mode; Google publishes `agy_acp_server` in the ACP registry (what Zed installs). codemax offers it from the switcher (size shown, dl.google.com only, into `~/.codemax/agents/antigravity-acp/<version>/`) and never bundles it (proprietary). It must run behind plain pipes (`plainPipes`: Bun's socket stdio gets no answer), signs in with `oauth-personal` only (`signIn`; never the API-key methods; a browser may open once; login lives in `~/.gemini/antigravity-acp/`). Verified live: permission prompts (reject honoured), models (Gemini 3.8 Flash High/Medium/Low; the Claude and GPT-OSS models `agy models` lists are refused by the ACP server with "not available for the current authentication method", so /model shows them greyed with `codemax --tui --agent antigravity`, read from `agy models` by `agyOnlyModels`), thinking level, modes default/auto_edit/yolo, resume, cancel. It reports only context fill, so usage is input-only, and it ends an interrupted turn with end_turn (the engine reports cancelled). Gemini CLI support was removed (Antigravity replaced it for Google AI plans); Warp shows its Gemini badge for Antigravity. |
| Grok inherits Claude Code's permission mode | Its own behavior; codemax warns when that mode is `auto`. Any agent that starts in a mode where it approves itself (Claude's auto / acceptEdits / bypassPermissions from the user's own settings, Antigravity's auto_edit / yolo, Codex's never) gets one warning line at start (`selfApprovingMode`): no prompts, so no diffs; Shift+Tab or /mode switches. codemax never changes that setting. |
| Handoffs resume from a step journal (`src/core/journal.ts`), not a summary | Every step (user request + snapshot, agent messages, reasoning, each tool call with input and result, plans, how each turn ended and what was in flight, handoffs) is appended as it happens, so a turn cut off by a limit leaves its trail. A fresh agent gets a resume packet (`buildResumePacket`): the task, where and why it stopped with the in-flight step, the plan with "continue here", the steps, and the real diff since the task's snapshot, within `brief.resumeChars`. An agent whose own session resumes gets only a catch-up of what others did since its last step (`buildCatchup`; last-seen comes from the journal, never `sessions.json`). The old turn brief remains for journal-less ledgers. The pre-switch summary turn is skipped when a journal exists. |
| Usage priced at public API rates, frozen per record | Shows the value a flat subscription covered; later price changes never rewrite history. Prices from OpenRouter, LiteLLM fallback, weekly. The agent's own figure wins wherever it reports one: Claude's (and OpenCode's) ACP `cost.amount` is a running total for the session, earlier runs included, so only what it adds counts (`agentTotalUsd` is kept on each record and given back as `costBaseline` when the session resumes; a lower total means it started again); the tokens of such an agent are counted but not priced again (`costCovered`); a tail's own cost (Grok's usage.json) is dropped when the agent also reports it over ACP. Claude's transcript repeats each message's usage on every content-block line, so `ClaudeUsageTail` counts a message once (plus any output a later line adds). Public prices are only the fallback (Codex reports tokens only; Antigravity only context fill; Cursor nothing). Older logs overcounted Claude (restarts re-counted the session total, tokens twice, both added): `resetOldUsageOnce` removed every project's usage.jsonl once (`usageV2` in config). |
| Brand theme in `src/chat/theme.ts`, dark and light palettes, `theme: auto` reads the terminal background | Pink is only the accent; warn/error/ok/plan keep distinct hues; overlays set their own text colour so light terminals stay readable. Colour themes over that base (`colors`, `COLOR_THEMES`, `BRAND`): codemax (pink, default), Claude Code (its 2.1.303 dark/light colours: orange #d77757 accent, blue selection), Ocean, Teal, Mono. Picked in setup, /config → Colours or `/theme <name>`; `/theme dark/light/auto` sets the base. A switch applies at once to the prompt, spinner, panels, footer and new lines (`recolor`); earlier transcript lines keep theirs until a restart. Snapshots per theme: `bun scripts/ui-preview.ts <dir> <theme>`. |
| Thinking, plans and separate messages are first-class | Agents stream reasoning (`thought_delta`), plans and `messageId`s; the transcript shows "Thinking… " with a 2-line preview of the reasoning (Ctrl+O for all of it; Claude Code hides it, but OpenCode and Cursor narrate only there, and hiding it left sessions of bare tool calls) and one paragraph per message; a run of reads, searches and listings (the agent's tools or read-only shell commands, `toolClass`; a "bash" announced first joins once its command is known) is one live line, "Reading 3 files, searching for 1 pattern…" with the latest step under it, then a dim line under the text column with the counts bold, "Read **3** files, searched for **1** pattern", no bullet and no hint (Claude Code 2.1.304's look; Ctrl+O lists the steps); anything that may change something keeps its own row; the spinner names the current step; the live turn's plan is pinned above the prompt as Claude Code's task list (`src/chat/tasks.ts`: "N tasks (X done, …)", ✔ struck through, ◼ in progress, ◻ open, 5 rows) (Ctrl+T folds it to its summary line and back, as Claude Code's task list; the spinner shows the task in progress in its active form, "Running the auth tests…", when no tool is running) and clears when a turn ends with all done, leaving one dim line in the chat (`✔ 3 tasks done: …`, `tasksDone`) so the plan can still be scrolled back to; replays keep it in the transcript. Ctrl+O expands everything cut short. Every agent's todo list lands there: Claude's TodoWrite comes as an ACP `plan` (the adapter's doing), Codex's update_plan as `turn/plan/updated`, and an agent whose list is only a tool call (OpenCode's `todowrite`, Cursor's `updateTodos` with `TODO_STATUS_*`, task lists with `tasks`/`items`) is read from the call's input (`todoPlan` in acp.ts, `todo-plan` in the debug log) and never shown as a tool row. |
| Per-turn usage from the ACP prompt response | OpenCode reports exact tokens there; `usage_update.used` is context fill (footer `ctx N%`), never added as tokens. Models/modes may arrive as ACP `configOptions` and are switched with `setSessionConfigOption`. |
| Limit detection is shared (`src/engines/errors.ts`) | Agents word it differently ("session limit · resets 3pm", "usage limit reached", 429 "free-usage-exhausted"). Errors and replies that are only a limit notice both trigger the handoff offer; such replies are not saved as answers, so the next agent gets the unanswered request. A plan that stopped paying counts too: Cursor's "Upgrade your plan to continue" (also as the last paragraph of a reply that did some work: the work is kept as the answer, the notice is not; `limit-in-reply`), OpenCode's `INVALID_PAYMENT_INSTRUMENT`, "credit balance is too low", "out of fast requests". |
| Handoff order (`handoffChain`, `/config` → Handoff order, a setup step) | A ranked list of agent + model ("Claude Code · Opus 5.5 → Cursor · Opus 5.5 → Antigravity · Gemini Flash"). At a limit (or a budget, or an agent that cannot run) `nextAgent` takes the next entry after the current one, then from the top, skipping agents not installed, out of quota, over budget or broken this run; the handoff switches to that entry's model (`launch`'s `model`; a new session also gets its agent's entry model, a resumed one keeps its own). `At a usage limit`: offer (one Enter), hand off automatically (`autoHandoff`), or nothing. Models come from the agent's own list (it is started briefly when not running). The order's first agent is the default agent (`order` follows it). |
| An agent whose own setup refuses every turn (`agentSetupFailure`: Antigravity's "The MCP server 'x' failed to initialize … to continue") | That reply is no answer: it is not saved, the turn is journaled as an error, the request stays for the next agent, codemax says how to fix it in the agent's own setup (`agy mcp` / `agy plugin`), marks the agent broken for this run and offers (or makes) the handoff. codemax passes agents no MCP servers of its own. |
| Side agent (`/config` only, `src/core/review.ts`, `src/chat/notes.ts`) | No slash commands: `/config` sets the agent, its model (picked from the agent's own list), how often it reviews (`sideAgent.every`, 0 = paused) and whether notes are forwarded automatically. Any harness can review the main agent's work after a working turn and reply NO_NOTE or one "Heads up" note. A note waits in a panel above the prompt (above the queue): 1 expands it, 2 sends it to the main agent to discuss (`forwardMessage`), 0 dismisses. A digit is always typed as text; only when the prompt holds just that digit for `NOTE_ARM_MS` (800 ms) does it act on the note and leave the prompt, so "2 more tests please" is a message. While the main agent's last reply asks you something (`asksUser`: ends in "?" or a "?" with a numbered list), the keys pause and a lone digit is your answer; they return after you reply. It never reviews on the main agent's own plan unless the user picked that agent explicitly (`sideAgent.samePlan`, also a `/config` row); after a handoff onto its tool, reviews pause with one note. Loop guard: a turn that only answers a forwarded note is never reviewed, auto mode sends at most 2 notes per task (`AUTO_FORWARD_CAP`), forwarded notes are follow-ups in the journal. It runs in its own persistent session with questions off, its permission requests are refused, it stays out of the journal, and it turns itself off at its usage limit. |
| Keep awake (`/awake on|lid`, `src/core/awake.ts`) | macOS caffeinate -dims (the display too, since a screen saver or lock looked like sleep; checked: PreventUserIdleDisplaySleep) (+ `pmset disablesleep` via a root watchdog for lid mode), Linux systemd-inhibit (sleep, shutdown, lid switch), Windows SetThreadExecutionState with ES_DISPLAY_REQUIRED (+ lid action set to do nothing). Every holder watches codemax's pid; changed settings are restored on quit, on crash (watchdog / restore record) and at next start. macOS and Windows cannot block shutdown. Real-machine check: `.github/workflows/awake.yml` (never run `scripts/awake-check.ts` on a user's machine). |
| Every new feature logs to the debug log (`debugEvent` / `debugOnce` from `src/core/debuglog.ts`; the owner's rule) | So problems with it show up in a user's `/debug export` without them describing it. At least: when it runs (with the counts, timings and choices that matter), when it fails (`errorFields(e)`), and any state it did not expect. Facts only, never conversation content: no message, reply, tool, file or diff text, only kinds, counts, lengths, ids, durations and scrubbed error messages. A test for the feature checks its event appears. |
| Settings live in one place (`/config`) | Every user-facing option is a row in `ChatApp.settings()` with its choices and an `apply` that takes effect at once and saves with `saveConfigKey`. Add new options there, not as one-off commands only. |
| Setup screen (`src/chat/onboarding.ts`, `/setup`) | Until `onboarded: true` is in config.json (new users, and everyone updating to it), codemax first walks through the `settings()` rows one per screen: ↑↓ choose, Enter applies and goes on, ← back, Esc keeps the defaults for the rest. Each step has a one-line why (`runOnboarding`'s `why`, also its order); follow-up rows appear only after the answer that needs them (side-agent details, what to do when checks fail); the side agent's model is left to /config (listing it starts the agent). Then the thread opens as usual; a default agent changed there is used. A new option needs a `why` line to appear in it. |
| Queued messages and the responding model are always visible | Messages typed while an agent works go through `enqueue()` and sit in a panel pinned above the prompt (`queueBox`) until sent. One rule decides (`busy()`: a turn, checks, a debate, an agent starting, a message being prepared, a switch, or the queue being sent): anything new while busy, or while the queue is not empty, joins the queue in order; your messages and forwarded side-agent notes alike. Between two queued messages the agent looks idle for a moment (the snapshot), and a note sent straight away there used to reach the agent as a second prompt at once, losing one. `drainQueue` runs once at a time, sends one message at a time, skips a message that fails (never the rest), and runs again after manual checks; `queue-add` / `queue-send` / `queue-error` go to the debug log. Ctrl+Enter (or Alt+Enter) sends now (`sendNow`): the typed text, or on an empty prompt the first queued message, goes to the front of the queue; a running turn is interrupted first (`send-now` in the debug log); a /command or ! runs as on Enter. ↑ on an empty prompt pulls the last queued message back for editing (↑ again moves to the one before): Enter puts it back in its place, clearing it and pressing Enter removes it, Esc restores it unchanged (`queueEdit`). The spinner and every turn's closing line name the agent and model, using the model the agent reported for that turn when it does (`turn.model`), shown by its listed display name. |
| Times are always 12-hour (`src/core/time.ts`) | `fmtTime12` / `fmtDateTime12` force en-US 12-hour ("7:25 PM", "Oct 18, 7:25 PM") whatever the locale; every message you send and every turn's closing line carry one. Never use `toLocaleTimeString()` directly. |
| Plan limits come from the agent, not a command | Claude Code's own `/usage` is terminal-only and the adapter never offers it, but the same data arrives on usage updates as `_meta["_claude/rateLimit"]`; codemax shows it in `/usage`, feeds quota from it, and a "rejected" window triggers the handoff offer. A window near its end (`allowed_warning`, or 80% used) shows Claude Code's own warning on the prompt's top border at the right (`showUpdateBadge` / `limitWarning`: "You've used 91% of your weekly limit · resets Fri 3:00 PM", red once reached; it outranks the update notice) and once per level in the transcript. Codex's `account/rateLimits/updated` (and rate limits in its usage) give 5-hour and weekly windows the same way (`codexWindows`). Agent warnings are shown too: ACP `notice` updates (advertised with `session.notices`, so Claude's "Retrying Claude, attempt 2 of 10", "Model fallback", "Fast mode turned off" no longer arrive as bold text inside the reply) and Codex's `warning`, `guardianWarning`, `configWarning`, `deprecationNotice` become a `notice` event: a transcript line, and 8 s on the prompt's border. Agent commands that clash with a built-in stay reachable as `/<agent>:<name>`. In the `/` palette, Tab writes the highlighted command into the prompt with a space after it (`onTab`; Enter runs it, or add arguments first), as in Claude Code; ↑↓ move. |
| A named agent is never swapped | `--agent X` (chat or `--tui`) stops with "X is not installed. Available: …" instead of starting another agent; without `--agent` the first installed one is used and named. Under `bun test` a fallback to a real agent throws, so tests can never spend quota. The adapter registry reads `CODEMAX_FAKE_AGENT` at call time. |
| Subagents are shown, never mixed in (`src/chat/subagents.ts`) | Engines emit `subagent` events (start, latest step, end). Claude: the Agent/Task tool call (`_meta.claudeCode.toolName`, `rawInput.subagent_type`) and child calls stamped `parentToolUseId`; OpenCode: its task tool (start/end only); Cursor: "Task: …" plus `cursor/task`; Codex: `subAgentActivity` items and the child's own thread. A Codex child thread's events never reach the main turn (its `turn/completed` used to end the main turn early), but its token usage is counted per thread, so /usage and budgets include helpers. ACP updates for another session id become subagent activity. The list sits under the prompt; finished agents show ✓ for 4 s. Background subagents (Claude `run_in_background`) end with the turn. Antigravity: its `invoke_subagent` tool call (recorded live from agy_acp_server 1.4.1) starts each entry of `rawInput.Subagents` (`Role`, `Prompt`, `TypeName`); the call completes as soon as they start and they send nothing of their own, so they run until the turn ends. Grok: its `spawn_subagent` tool (`persona` / `subagent_type`), mapped from the binary's tool names; not yet seen live (the probe hit Grok's free-usage limit). |
| Agent questions (`src/chat/question.ts`, `src/engines/elicitation.ts`) | ACP form elicitation is advertised, so Claude's AskUserQuestion (otherwise disabled by the adapter) and MCP forms open a dialog in codemax's slot with permission prompts: digits pick, typing fills "Other", Esc skips (the agent carries on). `questions` in `/config`: ask, skip after 5 min (unattended runs), or off (not advertised; new sessions). Codex: `item/tool/requestUserInput` (one field per question, "Other" when `isOther`) and MCP forms (`mcpServer/elicitation/request`) open the same dialog. In its default mode Codex only asks with the `default_mode_request_user_input` feature, which it labels under development: codemax turns it on per thread (`config` on thread/start, resume, fork) only while questions are not off, and starts the thread without it if Codex rejects it. Verified live with codex 0.159.3. |
| The prompt grows with its text | Up to 10 lines or a third of the screen, counted by `wrappedLines` (the textarea's own `virtualLineCount` lags). A fixed one-line box made a full line look like a new empty prompt. |
| Terminal tab status (`src/core/termstatus.ts`) | Warp has built-in logos only (no custom icon API, warpdotdev/warp#13519), so codemax speaks Warp's `warp://cli-agent` channel (OSC 777 + JSON, gated on `WARP_CLI_AGENT_PROTOCOL_VERSION`) as the agent it drives: the tab shows Claude Code / Codex / OpenCode / Cursor / Copilot (and Antigravity under its Gemini badge) with running / waiting / done, and Warp raises its own notifications. Other terminals get OSC 7501 status and a desktop notification (OpenTUI `triggerNotification`) when an agent waits or a turn over `bellAfterSeconds` ends while unfocused. A question (a dialog, or a reply that ends by asking you something: `asksUser`, `TerminalStatus.asked`, `agent-asks`) always notifies while unfocused, in Warp too (Warp was not seen acting on `question_asked`, and a missed question stalls the work). Everything goes through the renderer, never raw stdout. `/config`: Terminal tab status, Desktop notifications. |
| Models are shown by display name only (`displayModelName`) | "Opus 5.5", never "opus" or "claude-opus-5-5", in menus (one column, no id), footer, turn lines, /status, /usage and side-agent labels. Ids the list lacks are spelled out for Claude families. |
| An agent is installed only if its CLI runs (`src/adapters/detect.ts`) | A file on PATH is not enough: `<bin> --version` must exit 0 within 15 s. Stale npm shims on Windows were offered as switch targets. `engine` in the chat's detection implies installed, and `switchTo` refuses an agent that is not. |
| Typing stays smooth (measure with `scripts/type-bench.ts` and `scripts/pty-bench.ts` before and after UI changes) | Per key, codemax's own handling is under 1 ms; keys wait for at most one frame (60 fps) while an agent streams. Work repeated on every streamed chunk or key must not grow with the reply or the project: code is highlighted in 40-line pieces cached by text (`highlight.ts`; a 1,500-line block re-styled every 80 ms had blocked the event loop for 60 ms, now about 4 ms), palette filters prepare labels once, keep one sorted order and narrow from the previous matches as the query grows (`palette.ts`; @file over 20k files went from 8 ms to 1 ms a key), and the prompt is re-styled only when `!` mode flips. ## Gotchas

- The `web` dev server often keeps serving the old stylesheet after `globals.css` changes. Restart it with `.next` removed: `pkill -f "next dev"; rm -rf web/.next; cd web && bun run dev`.
- On this Mac, `bun build --compile` output must be re-signed or macOS kills it with exit 137. The build script does it.
- The user's terminal (Warp) swallows Ctrl+/; the working switcher hotkey is Ctrl+^.
- The Open Graph image loads fonts from Google Fonts at render time and falls back to Geist offline, so it renders on demand, not at build.
